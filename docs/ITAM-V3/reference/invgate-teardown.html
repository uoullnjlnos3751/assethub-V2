InvGate Asset Management ทำงานอย่างไร

บันทึกโครงสร้างและพฤติกรรมการทำงานทั้งหมดจากการกดใช้งานจริงด้วยบัญชี superadmin เพื่อใช้เป็นแบบอ้างอิงในการออกแบบระบบ IT Asset Management ของ TRR Group

เวอร์ชัน v3.20 CI Type 9 ชนิด ประเภทอุปกรณ์ 16 ชนิด เมนูหลัก 10 หมวดตั้งค่า 10 สำรวจเมื่อ 25 ส.ค. 2569
01

โมเดลข้อมูล — ทุกอย่างคือ CI

หัวใจของ InvGate คือทุกสิ่งในระบบเป็น Configuration Item (CI) ชนิดใดชนิดหนึ่ง ไม่ได้แยกเป็นตารางอิสระ หน้าจอ Create CI เผยรายการชนิดทั้งหมดไว้ชัดเจน

ชนิด CIบทบาทในระบบสถานะ
Assetsอุปกรณ์ที่จับต้องได้ แตกย่อยได้อีก 16 ประเภทใช้งานได้
Cloud Softwareบริการ SaaS / ทรัพยากรบนคลาวด์ใช้งานได้
Userพนักงาน เป็นได้ทั้งผู้ครอบครองและผู้ใช้ระบบใช้งานได้
Business Applicationระบบงานที่ประกอบจาก CI หลายตัว (นี่คือ CMDB)ใช้งานได้
Locationสถานที่แบบลำดับชั้นหลายระดับใช้งานได้
Contractสัญญา MA / ประกัน / Subscription / Licenseใช้งานได้
Vendorผู้ขายและผู้ให้บริการใช้งานได้
Purchase Orderใบสั่งซื้อ ผูกกลับไปยัง Asset ที่ได้มาBETA
Cost Centerศูนย์ต้นทุนสำหรับปันส่วนค่าใช้จ่ายBETA

ประเภทย่อยของ Assets ทั้ง 16 ชนิด — เพิ่มได้เองจาก Settings › ทรัพย์สิน › ประเภททรัพย์สิน

Access Point   Chromebook   Computer      Firewall
Headset       IP Camera    Monitor       Phone
Printer       Projector    Router        Server
Switch        Tablet       Videoconference VMware ESXi
สิ่งที่ควรเรียนรู้

เพราะทุกอย่างเป็น CI ชนิดหนึ่ง การเพิ่ม “เครื่องสแกนลายนิ้วมือ” จึงเป็นแค่การเพิ่ม Record ในตารางประเภท ไม่ต้องสร้างตารางใหม่และไม่ต้องแก้หน้าจอ นี่คือจุดที่ระบบ In-house ส่วนใหญ่พังในปีที่สอง เพราะไปแยกตารางตามประเภทตั้งแต่แรก

03

Explorer — หน้าจอเดียวใช้ซ้ำทุกโมดูล

ทุกโมดูลใช้หน้าตารางแบบเดียวกันหมด ต่างกันแค่ชุดคอลัมน์ ผู้ใช้จึงเรียนรู้ครั้งเดียวใช้ได้ทั้งระบบ

ส่วนประกอบพฤติกรรมจริงที่ทดสอบแล้ว
Saved viewsปุ่มซ้ายสุดเปิดรายการมุมมองที่บันทึกไว้ แต่ละมุมมองจำ Filter และคอลัมน์ของตัวเอง มี PREDEFINED ติดมาให้ และปักหมุดเป็นค่าเริ่มต้นได้
แถวกรองอยู่ใต้หัวตาราง มีช่องกรองของทุกคอลัมน์ ไม่มีตัวสร้างเงื่อนไขซับซ้อนแยกต่างหาก ปุ่มรูปกรวยคือ “ล้างตัวกรองทั้งหมด”
เรียงลำดับคลิกหัวคอลัมน์เพื่อสลับขึ้น-ลง มีลูกศรบอกทิศ
สลับมุมมองตาราง ↔ การ์ด การ์ดแสดง Chip สถานะ + Chip ประเภท + ไอคอน + ชื่อ + Inventory ID + คู่ป้าย/ค่า และแถบ “UPDATED A DAY AGO” ที่ท้ายการ์ด
แผงสรุปขวาแสดง Total Assets และ Current value เป็นตัวเลขใหญ่ พร้อม Pie ที่เลือกมิติได้ ตัวเลขคำนวณจากผลลัพธ์ที่กรองอยู่ และเปลี่ยนทันทีเมื่อเลือกแถว
เมนู ⋮ มุมขวาคอลัมน์ในตาราง (badge บอกจำนวน 11) · Table size (Auto) · Results per page (50) · Export CSV/XLSX
Tag ในตารางแสดงเป็น Chip สีคาสีตาม Tag ได้หลายอันต่อแถว
ค่าที่คลิกได้Manufacturer, Location, Owner, Model เป็นลิงก์ทั้งหมด กดแล้วไปหน้า Profile ของสิ่งนั้น

การทำงานแบบกลุ่ม

คำสั่งรายละเอียด

หนึ่ง — แผงสรุปด้านขวาคำนวณใหม่ตามสิ่งที่เลือกทันที เลือก 2 เครื่องก็เห็นมูลค่ารวมของ 2 เครื่องนั้นเลย สอง — ติ๊กหัวตารางเลือกได้แค่ “หน้าปัจจุบัน” (50 จาก 140) และบอกตัวเลขตรง ๆ ไม่หลอกว่าเลือกครบแล้ว

การสร้างรายการใหม่ — 3 ขั้น

ปุ่ม NEW CI ไม่เปิดฟอร์มทันที แต่ให้เลือกชนิดก่อนเพื่อให้ได้ฟอร์มที่ตรงกับสิ่งนั้นจริง ๆ

ขั้น 1  เลือกชนิด CI    → Assets · Cloud Software · User · Business Application
                            Location · Contract · Vendor · Purchase Order · Cost Center
ขั้น 2  เลือกประเภทย่อย → Computer · Switch · Printer · IP Camera · … (16 ชนิด)
ขั้น 3  กรอกฟอร์ม       → Create multiple CIs

ฟอร์มขั้นที่ 3 แบ่งเป็นกลุ่ม และรองรับการสร้างทีละหลายเครื่องในครั้งเดียว

กลุ่มฟิลด์
ข้อมูลหลักFormat บังคับ · Status บังคับ · Manufacturer บังคับ · Location
FinancialsInvoice · Acquisition date · Acquisition type · Acquisition cost · Annual depreciation percentage · Cost center
List optionsNumber of assets to create · Columns to enter · Inventory ID Scan/Manual
Listตารางย่อยกรอกเฉพาะค่าที่ต่างกันรายเครื่อง — Inventory ID · Name · Serial Number
นี่คือกลไกที่ฉลาดที่สุดที่เจอในระบบนี้

กรอกค่าที่เหมือนกัน (ยี่ห้อ สถานที่ ราคา ค่าเสื่อม) ครั้งเดียว ระบุจำนวนเครื่อง แล้วเลือกว่ามีคอลัมน์ไหนบ้างที่ต่างกันรายเครื่อง จากนั้นพิมพ์เฉพาะคอลัมน์เหล่านั้น — ตอนรับ Notebook เข้ามา 10 เครื่องพร้อมกันจะเร็วขึ้นมหาศาล และช่อง Inventory ID รองรับเครื่องสแกนบาร์โค้ดโดยตรง

8 กลไกที่ควรลอกไปใช้

เรียงตามผลกระทบต่อระบบจริง จากมากไปน้อย

#กลไกเหตุผล
1CI เป็นฐานกลาง + ประเภทเป็น Configเพิ่มประเภทอุปกรณ์ใหม่โดยไม่ต้องรื้อระบบ เป็นเรื่องที่แก้ทีหลังไม่ได้
2Audit trail เก็บค่าเดิม/ค่าใหม่ระบบส่วนใหญ่เก็บแค่ “ใครแก้ตอนไหน” พอ Audit จริงตอบไม่ได้ ต้องออกแบบตั้งแต่วันแรก
3สร้างทีละหลายเครื่องด้วยฟอร์มเดียวประหยัดเวลารับของเข้าคลังมากที่สุดในบรรดาฟีเจอร์ทั้งหมด
4ทุกค่า Lookup คลิกไปหน้า Profile ได้Manufacturer, Location, Vendor มีหน้าและสถิติของตัวเอง ทำให้ไล่ข้อมูลได้ลื่นโดยไม่ต้องกลับไปค้นใหม่
5Smart tag ที่ติดอัตโนมัติตามกฎเป็นการจัดกลุ่มแบบไม่ต้องมีคนดูแล เช่น “อุปกรณ์ไม่มีผู้ครอบครอง”
6แผงสรุปที่คิดตามผลลัพธ์ที่กรองกรองเสร็จเห็นยอดรวมกับมูลค่าทันที ไม่ต้องส่งออกไปรวมใน Excel
7Health rule ที่บอกด้วยว่ากฎไหนตัดสินผู้ใช้เชื่อถือผลได้เพราะตรวจสอบที่มาได้
8QR ต่อชิ้นและต่อกลุ่มเปลี่ยนการตรวจนับประจำปีจากไล่จดเป็นเดินสแกน
