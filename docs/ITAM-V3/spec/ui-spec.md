# UI Specification — สิ่งที่ลอกจากต้นแบบ และสิ่งที่ตั้งใจทำต่าง

เอกสารนี้อธิบาย "แบบ" ของหน้าเว็บ เพื่อให้พัฒนาหน้าใหม่แล้วยังกลมกลืนกับของเดิม
ไฟล์จริง: `public/styles.css` (Design tokens อยู่บนสุด) และ `public/app.js`

## 5. ที่ลอกจากต้นแบบ (InvGate)

| สิ่งที่ลอก | เหตุผล |
|---|---|
| แถบเมนูซ้ายสีเข้ม ย่อเป็นไอคอนได้ | ประหยัดพื้นที่ตอนดูตารางกว้าง |
| Explorer = ตาราง + ช่องกรองรายคอลัมน์ + แผงสรุปด้านขวา | ใช้งานจริงเร็วกว่าหน้ากรองแยก |
| แถบคำสั่งกลุ่มเมื่อเลือกหลายแถว | งาน IT มักทำทีละหลายเครื่อง |
| หน้ารายละเอียดแบบแท็บ + การ์ดสรุปด้านบน | เห็นสถานะสำคัญก่อนโดยไม่ต้องเลื่อน |
| แท็บ Applications 3 ชั้น + ชิปตัวกรองถอดได้ | โครงที่ผู้ใช้ต้นแบบคุ้นอยู่แล้ว |
| ชื่อไอคอนและตำแหน่งเมนู | ดู `reference/invgate-icons.md` |

**ไอคอนวาดขึ้นใหม่ทั้งชุด** (83 path ใน `public/app.js` ส่วนที่ 1) ไม่ได้คัดลอกไฟล์ SVG ของต้นแบบ
เก็บไว้แค่ชื่อไฟล์เป็นข้อมูลอ้างอิงว่าไอคอนแต่ละตัวเป็นรูปอะไร

## 6. ที่ตั้งใจทำต่างจากต้นแบบ

| ต้นแบบ | ของเรา | ทำไม |
|---|---|---|
| กราฟวงกลม 12 ส่วนบนแดชบอร์ด | บาร์แนวนอน | วงกลมที่มีเกิน 6 ส่วนอ่านไม่ออก |
| ไม่เตือนซอฟต์แวร์ต้องห้ามในหน้าเครื่อง | แถบเตือน + ขีดแดงหน้าแถว | ตรงกับงาน Compliance ที่ต้องใช้จริง |
| ตารางวาดใหม่ทั้งหมดตอนกรอง | หรี่ตารางแทน | ช่องกรองไม่หลุดโฟกัสระหว่างพิมพ์ |
| ภาษาอังกฤษ | ไทยทั้งหมด + พ.ศ. | ผู้ใช้ปลายทางเป็นคนไทย |
| ไม่มี QR | QR ต่อเครื่อง + PWA สแกนจากมือถือ | ตรวจนับทรัพย์สินหน้างาน |

## 7. กติกาที่ต้องรักษาเมื่อเขียนหน้าใหม่

1. `[hidden]{display:none !important}` **ต้องอยู่บรรทัดแรกของ styles.css** — CSS ของเราชนะ UA stylesheet เสมอ ถ้าไม่มีบรรทัดนี้ กล่องที่ตั้ง `hidden` จะยังแสดงและบังคลิกทั้งหน้า (เคยเกิดจริง)
2. ข้อความที่มาจากข้อมูลผู้ใช้ต้องผ่าน `esc()` ทุกจุด
3. ตารางกว้างต้องอยู่ใน `.tbl-scroll` — หน้าเว็บห้ามเลื่อนแนวนอนทั้งหน้า
4. เพิ่มคอลัมน์ใหม่ในตาราง = ต้องเพิ่มชื่อคอลัมน์ใน allowlist ฝั่งเซิร์ฟเวอร์ด้วย ไม่งั้นกรอง/เรียงจะเงียบ
5. ทุกปุ่มไอคอนต้องมี `aria-label`
6. ทดสอบทั้งโหมดสว่างและโหมดมืดก่อนถือว่าเสร็จ
