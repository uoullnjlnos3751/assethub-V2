## 1. สิ่งที่พบ: เรามีเกือบครบแล้ว แต่ไม่มีข้อมูล

ระบบนี้มี **73 ตาราง** ครอบคลุมเกือบทุกความสามารถที่ Unduit โฆษณา
ปัญหาไม่ใช่ "ขาดฟีเจอร์" แต่คือ **ฟีเจอร์มีอยู่แล้วและว่างเปล่า**

| ความสามารถของ Unduit | เรามีโครงสร้างไหม | ข้อมูลจริง |
|---|---|---|
| Asset Inventory & Registry | ✅ มี | **815 รายการ · serialNo 100%** — แข็งแรง |
| User & Assignment Management<br>(chain of custody) | ✅ มี `assetHistory`, `custodyHolder` | ประวัติ 472 รายการ · custody 81 (เพิ่งเริ่มใช้) |
| Automated Discovery | ✅ มี Agent + GLPI sync | **33 / 815 = 4%** ← คอขวดตัวจริง |
| Workflow Automation | 🟡 มี `notificationOutbox` (257) | ไม่มี trigger อัตโนมัติข้ามโมดูล |
| SaaS Discovery | ❌ ไม่มี | — |
| License & Spend Management | ✅ มี `softwareLicense`, `contract` | **License 0 · Contract 0** ตารางว่าง |
| Warranty & Refresh Tracking | ✅ มี `warrantyEndDate` | **8 / 815 = 1%** ← นี่คือเหตุผลที่การ์ด "ใกล้หมดประกัน" ว่างเปล่า |
| Reporting & Audit Trail | ✅ มี + รายงานจัดซื้อ | ใช้งานได้จริง |
| Mobile (สแกน/มอบหมาย) | ❌ ไม่มี | เดสก์ท็อปอย่างเดียว |

**ความครบของข้อมูลตลอดวงจรชีวิต**

```
serialNo        815  100%   ████████████████████
ผู้ขาย/vendor   311   38%   ███████
วันที่ซื้อ      225   28%   █████
วันหมดประกัน      8    1%   ▏
ราคาซื้อ          4    0%   ▏
```

โมดูลที่มีตารางแต่ยังไม่มีข้อมูลเลย: **ยืม-คืน 0 · ส่งมอบ 0 · License 0 · สัญญา 0 · จำหน่ายออก 0**

## 2. สิ่งที่ควรยืมจาก Unduit (และสิ่งที่ไม่ควร)

### ✅ ควรยืม

**2.1 จัดระเบียบตาม "วงจรชีวิต" แทน "โมดูล"**

Unduit เล่าเรื่องเป็นเส้นเดียว: จัดหา → ส่งมอบ → ดูแล → เรียกคืน → จำหน่าย
ของเราจัดตามเมนู: ทะเบียน / ยืม-คืน / PM / จำหน่าย ซึ่งทำให้โมดูลว่างดูเหมือน "เมนูที่ไม่มีใครใช้"
พอจัดเป็นวงจรชีวิต โมดูลว่างจะกลายเป็น **"ช่วงที่ยังไม่มีข้อมูล"** ซึ่งเป็นข้อเท็จจริงที่ใช้ตัดสินใจได้

**2.2 นำด้วยผลลัพธ์ ไม่ใช่จำนวน**

เขาขึ้นต้นด้วย *"ลดต้นทุน 30% · เร็วขึ้น 2 เท่า"* ไม่ใช่ *"เรามี 815 รายการ"*
ของเรามีวัตถุดิบอยู่แล้ว — รายงานจัดซื้อบอกได้ว่าปีนี้เสนอเปลี่ยนแบตกี่เครื่อง ประหยัดจากการเพิ่ม RAM
แทนการเปลี่ยนเครื่องกี่เครื่อง แต่ตัวเลขพวกนี้ไม่เคยขึ้นหน้าแรก

**2.3 Chain of custody เป็นของหลัก ไม่ใช่แท็บรอง**

*"Always know who has what"* — ของเรามี `assetHistory` 472 รายการ + custody ที่เพิ่งเริ่มใช้
แต่หน้าทรัพย์สินยังเอาสเปกขึ้นก่อน ทั้งที่คำถามที่ถูกถามบ่อยที่สุดคือ "เครื่องนี้ตอนนี้อยู่กับใคร และก่อนหน้านี้อยู่กับใคร"

**2.4 มือถือสำหรับสแกน**

*"Scan, assign, and manage assets anywhere"* — งานที่เดินไปทำหน้างานจริงมีสองอย่างในระบบนี้แล้ว
คือ **ทำ PM** กับ **ตรวจนับ** ทั้งคู่ตอนนี้ต้องกลับมานั่งหน้าคอม

### ❌ ไม่ควรยืม

**SaaS Discovery** — เป็นจุดขายของเขา แต่องค์กรนี้ยังไม่มีปัญหา shadow IT ที่วัดได้ และการทำต้องต่อกับ SSO/Netflow ซึ่งใหญ่กว่าประโยชน์ที่จะได้ตอนนี้มาก

**หน้าตาแบบ landing page** — hero ตัวใหญ่ ส้มจัด testimonial สไลด์ ไม่มีที่ยืนในจอที่ใช้ทำงานทุกวัน

**คำว่า "AI Driven"** — ระบบนี้มี Agent ที่อ่านสภาพเครื่องจริงและช่วยตอบ checklist ได้แล้ว ซึ่งมีประโยชน์กว่าการติดป้าย AI

## 4. ลำดับที่แนะนำ

```
สัปดาห์นี้     1 → 2 → 3     (โค้ด · เห็นผลทันที)
เดือนนี้       4 → 6         (ข้อมูล · ปลดล็อกของที่มีอยู่)
ไตรมาสนี้      5             (ปฏิบัติการ · ผลมากที่สุดแต่ใช้เวลา)
หลังจากนั้น    7 → 8 → 10 → 9
```

**ข้อ 5 (ขยาย Agent) เป็นตัวคูณของทุกอย่าง** — ทุกฟีเจอร์ที่สร้างมาในรอบหลัง (fleet health, agent ช่วยทำ PM,
รายงานจัดซื้อหัวข้อแบตเตอรี่, ดึงสเปกตอนเพิ่มทรัพย์สิน) ล้วนถูกจำกัดด้วยตัวเลข 4% ตัวเดียวกัน
