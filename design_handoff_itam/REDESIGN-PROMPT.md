# คำสั่งสำหรับปรับหน้าตาเว็บเดิมให้เหมือนต้นแบบ

> ใช้เมื่อ **มีระบบทำงานอยู่แล้ว** และต้องการเปลี่ยนแค่ UI ไม่ใช่เขียนใหม่ทั้งหมด
> ถ้าจะสร้างระบบใหม่ตั้งแต่ต้น ให้ใช้ `CLAUDE.md` แทน

---

## ข้อความที่ให้วางใน Claude Code

```
โปรเจกต์นี้เป็นระบบบริหารทรัพย์สินไอทีที่ทำงานอยู่แล้ว
ผมต้องการปรับ "หน้าตา" ให้ตรงกับต้นแบบในโฟลเดอร์ design_handoff_itam/
โดยไม่เปลี่ยนตรรกะการทำงาน

อ่านตามลำดับ:
1. design_handoff_itam/DESIGN-TOKENS.md  ← สี ตัวอักษร ระยะห่าง component pattern
2. design_handoff_itam/SCREENS.md        ← โครงหน้าและเนื้อหาของแต่ละหน้า
3. ไฟล์ .dc.html ในโฟลเดอร์นั้น          ← เปิดดูหน้าตาจริง (อย่าคัดลอกโค้ด)

กฎการทำงาน:
- ห้ามแก้ API call, state management, business logic, routing
- แก้เฉพาะ JSX/HTML structure, CSS/Tailwind class, และ component ที่ใช้แสดงผล
- ข้อมูลทั้งหมดยังต้องมาจาก API เดิม ตัวเลขในต้นแบบเป็นแค่ตัวอย่าง
- ถ้าหน้าเดิมมีฟีเจอร์ที่ต้นแบบไม่มี ให้เก็บไว้ อย่าลบ
- ถ้าต้นแบบมีอะไรที่หน้าเดิมไม่มี ให้บอกผมก่อน อย่าเพิ่งสร้าง

เริ่มจาก:
ขั้นที่ 1 — สร้างชั้น design token (CSS variables หรือ Tailwind config)
           ตาม DESIGN-TOKENS.md ให้ครบทุกค่า
ขั้นที่ 2 — สร้าง/ปรับ shared component ให้ตรงต้นแบบ:
           Card, Table, Chip สถานะ, ปุ่มหลัก/รอง, แถบแท็บย่อย,
           การ์ด KPI, สวิตช์, แถบความคืบหน้า, กล่องข้อความเตือน,
           ปุ่มจัดการในตาราง (แก้/ลบ/ลากเรียง), Avatar
ขั้นที่ 3 — ไล่ปรับทีละหน้า เริ่มจากหน้าภาพรวม แล้วรอผมยืนยันก่อนไปหน้าถัดไป

ก่อนเริ่ม ให้สำรวจโค้ดเบสแล้วบอกผมว่า:
- ตอนนี้ใช้ระบบ styling อะไร (Tailwind / CSS Modules / styled-components / อื่น ๆ)
- มี component library อยู่แล้วหรือไม่ ชื่ออะไร
- มีหน้าอะไรบ้าง และหน้าไหนตรงกับต้นแบบหน้าไหน
- แผนที่จะปรับ เรียงตามลำดับ
```

---

## ลำดับที่แนะนำ

ไล่ทีละหน้า อย่าทำทั้งระบบพร้อมกัน — จะรีวิวไม่ทันและ merge ยาก

| ลำดับ | หน้า | เหตุผล |
| --- | --- | --- |
| 1 | Design token + shared component | ทุกหน้าใช้ร่วมกัน ทำก่อนได้ผลกว้างสุด |
| 2 | โครงหน้า (แถบเมนูซ้าย + หัวหน้าจอ) | เห็นผลทันทีทุกหน้า |
| 3 | หน้าภาพรวม | หน้าแรกที่ผู้ใช้เห็น |
| 4 | รายการทรัพย์สิน | ตารางหลัก เป็นแม่แบบให้ตารางอื่น |
| 5 | ยืม–คืน | ใช้บ่อยที่สุด |
| 6 | หน้าที่เหลือ | ตามลำดับความถี่การใช้งาน |
| 7 | สถานะระบบ (โหลด/ว่าง/ผิดพลาด) | เก็บรายละเอียดท้ายสุด |

## ประโยคที่ใช้บ่อยระหว่างทำงาน

**ปรับทีละหน้า**
```
ปรับหน้า <ชื่อหน้า> ให้ตรงกับ SCREENS.md หัวข้อ "<ชื่อหัวข้อ>"
ใช้ shared component ที่สร้างไว้แล้ว อย่าเขียน style ซ้ำ
เก็บ API call และ state เดิมไว้ทั้งหมด
```

**เทียบกับต้นแบบ**
```
เปิด design_handoff_itam/ITAM Dashboard Light.dc.html
เทียบกับหน้า <ชื่อหน้า> ในโปรเจกต์ แล้วบอกผมว่าต่างกันตรงไหนบ้าง
เรียงตามความสำคัญ ยังไม่ต้องแก้
```

**เมื่อโครงข้อมูลไม่ตรง**
```
ต้นแบบมีคอลัมน์ <ชื่อ> แต่ API เดิมไม่มีข้อมูลนี้
บอกผมว่าต้องเพิ่มอะไรที่ backend บ้าง อย่าเพิ่งใส่ค่าปลอม
```

**เก็บรายละเอียดท้ายงาน**
```
ไล่ตรวจทุกหน้าที่ปรับแล้ว ว่ามีครบทั้ง 5 สถานะหรือยัง:
กำลังโหลด (skeleton) · ยังไม่มีข้อมูล · ค้นหาไม่พบ · ผิดพลาด · ไม่มีสิทธิ์
อ้างอิง design_handoff_itam/ITAM States.dc.html
```

## ข้อควรระวัง

- **อย่าให้แก้ทั้งระบบในครั้งเดียว** — diff จะใหญ่จนรีวิวไม่ได้ และถ้าพังจะหาสาเหตุยาก
- **แยก branch ต่อหน้า** — `redesign/dashboard`, `redesign/assets` เป็นต้น
- **ตรวจว่ายังใช้งานได้จริงหลังปรับทุกหน้า** — การเปลี่ยน markup อาจทำ test หรือ selector พัง
- **ถ้าโค้ดเบสเดิมใช้ component library** (MUI, Ant Design, Chakra) — ให้ปรับ theme ของ library นั้นแทนการเขียนทับ จะได้ไม่ชนกัน
- **ต้นแบบออกแบบที่ความกว้าง 1920px** — ต้องบอก Claude Code ให้ทำ responsive เพิ่มเอง ถ้าเว็บเดิมรองรับจอเล็ก
