# Handoff: ระบบบริหารทรัพย์สินไอที (IT Asset Management — ITAM)

## Overview

ระบบบริหารทรัพย์สินไอทีสำหรับองค์กรหลายบริษัทในเครือ ครอบคลุมวงจรชีวิตทรัพย์สินตั้งแต่จัดซื้อ ลงทะเบียน ติดตั้ง ส่งมอบ ยืม–คืน บำรุงรักษา ตรวจนับ จนถึงตัดจำหน่าย พร้อมงานหลังบ้าน (ผู้ใช้/สิทธิ์ ข้อมูลหลัก การเชื่อมต่อระบบภายนอก รายงาน)

ออกแบบต่อยอดจาก repo เดิม `uoullnjlnos3751/assethub-V2` (branch `master`, path `frontend/src`) — ดู `github.md` ที่ราก project สำหรับ screen map ระหว่างหน้าจอกับไฟล์ต้นทาง

**ขอบเขต:** 13 เมนูหลัก ประมาณ 80 หน้าจอย่อย + หน้าเข้าสู่ระบบ + 4 หน้าจอมือถือ + 9 สถานะระบบ + เอกสารพิมพ์ A4 3 ฉบับ

## About the Design Files

ไฟล์ในชุดนี้เป็น **design reference ที่เขียนด้วย HTML** — เป็นต้นแบบแสดงหน้าตาและพฤติกรรมที่ต้องการ ไม่ใช่โค้ดที่นำไป deploy ได้

งานที่ต้องทำคือ **สร้างหน้าจอเหล่านี้ขึ้นใหม่ในโค้ดเบสจริง** โดยใช้ pattern และ library ที่โปรเจกต์นั้นใช้อยู่ (assethub-V2 เป็น React + TypeScript อยู่แล้ว — ให้ทำตามโครงสร้าง `pages/`, `components/` เดิม) ไม่ใช่คัดลอก HTML ไปวาง

ทุกตัวเลขในไฟล์เป็นข้อมูลตัวอย่างเพื่อการออกแบบ ต้องแทนด้วยข้อมูลจริงจาก API

## Fidelity

**High-fidelity** — สี ตัวอักษร ระยะห่าง และสถานะปฏิสัมพันธ์เป็นค่าสุดท้ายที่ตั้งใจให้ใช้จริง ให้ทำตามค่าที่ระบุใน `DESIGN-TOKENS.md` อย่างเคร่งครัด

ข้อยกเว้น: ภาพผังห้องปฏิบัติการบนหน้าภาพรวมเป็นภาพประกอบเชิงแนวคิด — ให้ปรับตามความเหมาะสมได้ ไม่ต้องทำ pixel-perfect

## สถาปัตยกรรมที่แนะนำ

```
Frontend   React 18 + TypeScript + Vite (ตาม assethub-V2 เดิม)
           React Router · TanStack Query · Zod (validation)
Backend    Node/NestJS หรือ .NET — REST + JWT
Database   PostgreSQL หรือ SQL Server
Auth       Microsoft Entra ID (OIDC) + LDAPS sync ผู้ใช้จาก AD
Storage    Azure Blob (ไฟล์แนบ รูปถ่าย ใบรับรองการล้างข้อมูล)
Jobs       cron/Hangfire — ซิงก์ AD, คำนวณค่าเสื่อม, แจ้งเตือน, สำรองข้อมูล
```

**ข้อกำหนดที่กระทบสถาปัตยกรรมตั้งแต่ต้น**

1. **Multi-tenant ระดับบริษัท** — ทุก query ต้องกรองด้วย `companyId` ของผู้ใช้ที่ล็อกอิน ยกเว้น SUPERADMIN ควรบังคับที่ชั้น repository/row-level security ไม่ใช่ที่ UI
2. **ทุก entity มี audit trail** — createdBy/At, updatedBy/At และ log การเปลี่ยนสถานะ
3. **ค่าเสื่อมคำนวณเป็น snapshot รายเดือน** ไม่คำนวณสดตอน query
4. **AD เป็นแหล่งข้อมูลผู้ใช้ฝ่ายเดียว** — ระบบอ่านอย่างเดียว ไม่เขียนกลับ

## แผนการทำงานที่แนะนำ (ลำดับความสำคัญ)

### Phase 1 — แกนระบบ (จำเป็นก่อนใช้งานจริง)
1. Auth + Entra ID SSO + AD sync job + role mapping จาก AD group
2. Company scope + row-level filtering
3. Master Data: บริษัท หมวดทรัพย์สิน ยี่ห้อ ที่ตั้ง ผู้ขาย หน่วยนับ
4. ทะเบียนทรัพย์สิน: CRUD + ค้นหา + นำเข้า Excel พร้อม validate
5. หน้าภาพรวม (KPI จากข้อมูลจริง)

### Phase 2 — งานประจำวัน
6. ยืม–คืน: คำขอ → IT Admin อนุมัติขั้นเดียว → จ่ายของ → รับคืน
7. ซ่อมบำรุง: ใบแจ้งซ่อม SLA เบิกอะไหล่
8. คลังอะไหล่: รับเข้า เบิกออก จุดสั่งซื้อ
9. QR/สติกเกอร์ + สแกน

### Phase 3 — เครื่องใหม่และ PM
10. เครื่องใหม่ & ส่งมอบ: ทะเบียน + อุปกรณ์ต่อพ่วง + Setup Checklist + ส่งมอบ + ยืนยันรับผ่าน MS Form/Power Automate
11. เครื่องหมุนเวียน + Offboarding
12. แผน PM + Template + PM Run + Gantt

### Phase 4 — การเงินและรายงาน
13. ค่าเสื่อมราคา + ส่งออกให้บัญชี
14. ตรวจนับประจำปี
15. ตัดจำหน่าย/บริจาค
16. รายงานทั้งหมด + ตั้งเวลาส่งอัตโนมัติ

### Phase 5 — ส่วนเสริม
17. หน้าจอมือถือ (PWA + ออฟไลน์)
18. เชื่อมต่อ GLPI, ERP, HR, Print Server
19. API Key management

## Assets

- **ฟอนต์:** IBM Plex Sans Thai (ข้อความไทย) + IBM Plex Sans (ตัวเลขและรหัส) — Google Fonts
- **ไอคอน:** inline SVG stroke-based (stroke-width 1.8–1.9) — แทนด้วย icon library ของโค้ดเบสได้ (แนะนำ Lucide)
- **โลโก้องค์กร:** ยังไม่มีไฟล์จริง — ระบบต้องมีช่องอัปโหลดที่ ตั้งค่า › ทั่วไป
- **ภาพประกอบ:** ผังห้องปฏิบัติการบนหน้าภาพรวมวาดด้วย CSS ล้วน ไม่มีไฟล์ภาพ
