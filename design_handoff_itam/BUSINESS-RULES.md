## 1. ขอบเขตตามบริษัท (Company Scope) — สำคัญที่สุด

ทรัพย์สินทุกชิ้นผูกกับบริษัทเจ้าของ (`Asset.companyId`) ผู้ใช้ทุกคนผูกกับบริษัทเดียว (`User.companyId` ดึงจากฟิลด์ `company` ใน AD)

**กฎ**
1. ผู้ใช้เห็นและยืมได้เฉพาะทรัพย์สินที่ `asset.companyId === user.companyId`
2. ทรัพย์สินของบริษัทอื่น **ต้องไม่ปรากฏ** ในผลค้นหา ตัวกรอง รายงาน หรือ API response — แม้ค้นด้วยเลขครุภัณฑ์ตรง ๆ (คืน 404 ไม่ใช่ 403 เพื่อไม่ให้เดาการมีอยู่ได้)
3. ทรัพย์สินที่ตั้ง `isShared = true` เห็นได้ทุกบริษัท
4. SUPERADMIN เห็นทุกบริษัท · IT_ADMIN เห็นเฉพาะบริษัทที่ตนดูแล
5. ห้ามยืมข้ามบริษัท — การย้ายทรัพย์สินข้ามบริษัทต้องทำผ่านเมนูโอนย้ายและบันทึกเป็นการขาย/โอนระหว่างบริษัทตามมาตรฐานบัญชี
6. มีสวิตช์ในหน้าตั้งค่าเปิดยืมข้ามบริษัทได้ — ถ้าเปิด ต้องให้ IT Admin ทั้งสองฝั่งอนุมัติ (ค่าเริ่มต้น: ปิด)

**วิธีบังคับใช้:** row-level security ที่ฐานข้อมูล หรือ global query filter ที่ ORM — ห้ามเขียนเงื่อนไขซ้ำในแต่ละ query

**บริษัทในเครือ (ตัวอย่างข้อมูล)**

## 2. การอนุมัติการยืม — IT Admin ขั้นเดียว

**ไม่มี** ขั้นอนุมัติตามมูลค่า และ **ไม่มี** สายบังคับบัญชา

```
1. ผู้ใช้ยื่นคำขอ          เลือกได้เฉพาะทรัพย์สินของบริษัทตนเอง
2. เข้าคิว IT Admin        จ่ายให้ IT Admin ของบริษัทเจ้าของทรัพย์สินอัตโนมัติ
3. IT Admin อนุมัติ/ปฏิเสธ  ปฏิเสธต้องระบุเหตุผล · แจ้งผู้ขอทันที
4. จ่ายของ                 IT Admin คนใดก็ได้ในบริษัทเดียวกัน
5. รับคืนและตรวจสภาพ        IT Admin คนใดก็ได้ในบริษัทเดียวกัน
```

- หัวหน้าผู้ขอได้รับ **สำเนาอีเมลเพื่อรับทราบ** ไม่ต้องกดอนุมัติ
- ต้องอนุมัติภายใน **1 วันทำการ** — เกินแล้วเตือน IT Admin ทุกเช้า 09:00
- IT Admin ไม่อยู่ → ส่งต่อ IT Admin คนอื่นในบริษัทเดียวกันโดยอัตโนมัติ
- ผู้อนุมัติเป็นนโยบายระบบ ตั้งค่าเปลี่ยนไม่ได้จาก UI

## 3. กฎการยืม

| กฎ | ค่า |
| --- | --- |
| ระยะเวลายืมสูงสุด | 30 วัน |
| ต่ออายุได้ | 2 ครั้ง ครั้งละ 15 วัน |
| ยื่นขอต่ออายุล่วงหน้า | ไม่น้อยกว่า 3 วันทำการ |

- ระยะเวลาเกิน 30 วัน → ไม่ให้ส่ง

## 4. เลขครุภัณฑ์และค่าเสื่อมราคา

**รูปแบบรหัส:** `IT-{อักษรย่อหมวด}-{ปี พ.ศ.}-{ลำดับ 4 หลัก}` เช่น `IT-NB-2569-0431`
- ออกอัตโนมัติ ต่อเนื่องรายปี
- แก้ไขภายหลังไม่ได้
- อุปกรณ์ต่อพ่วงใช้รูปแบบเดียวกัน
- อักษรย่อหมวดห้ามซ้ำ · แก้อักษรย่อไม่เปลี่ยนเลขที่ออกไปแล้ว

- วิธีเส้นตรง · มูลค่าซาก ฿0

- การเปลี่ยนอายุใช้งานมีผลกับทรัพย์สินที่ลงทะเบียนใหม่เท่านั้น รายการเดิมใช้เกณฑ์ตอนลงทะเบียน

**บังคับตอนลงทะเบียน**
- Serial Number บังคับทุกหมวดยกเว้นอุปกรณ์ต่อพ่วง
- ตรวจ Serial ซ้ำกับทะเบียนเดิม → เตือนทันที
- แนบใบสั่งซื้อหรือใบส่งของ สำหรับราคาเกิน ฿10,000
- ราคาทุนต้องมากกว่า 0

## 5. เครื่องใหม่และการส่งมอบ

**ประเภทการส่งมอบ 3 แบบ**
| ประเภท | ทะเบียน | Checklist | ค่าเสื่อม |
| --- | --- | --- | --- |
| เครื่องใหม่ | สร้างใหม่ | IT-WI-001 (31 ข้อ) | เริ่มนับใหม่ |
| เครื่องหมุนเวียน | ใช้เลขเดิม | IT-WI-006 (18 ข้อ) | เดินต่อ ไม่รีเซ็ต |
| เครื่องทดแทนชั่วคราว | ใช้เลขเดิม | ย่อ 9 ข้อ | ไม่เปลี่ยนผู้ครอบครองถาวร |

**เครื่องหมุนเวียน — กฎเพิ่มเติม**
- เครื่องอายุเกิน 5 ปี หรือค่าซ่อมสะสมเกิน 40% ของราคาทุน → ระบบเสนอตัดจำหน่ายแทนการจ่ายซ้ำ
- ต้องมี `WipeRecord` ครบถ้วนก่อนกดส่งมอบ (วิธี เครื่องมือ ผู้ทำ วันที่ ผลตรวจสอบ ใบรับรอง ผู้ตรวจซ้ำ)
- แบตเตอรี่ต้องมีสุขภาพ ≥ 70%
- สำรองข้อมูลเครื่องเก็บไว้ 30 วันก่อนล้าง
- ใบส่งมอบและอีเมลต้องมีกล่องแจ้งสภาพเครื่อง: อายุใช้งาน · สถานะประกัน · ประวัติซ่อม · การล้างข้อมูล
- อุปกรณ์ต่อพ่วงเลือกทีละชิ้นว่าใช้ของเดิมหรือเบิกใหม่ — ตัดสต็อกเฉพาะที่เบิกใหม่

**การยืนยันรับ**
- ส่งอีเมลถึงผู้รับ สำเนาหัวหน้า HR และฝ่ายไอที พร้อมลิงก์ MS Form
- ต้องยืนยันภายใน 3 วันทำการ
- ไม่ยืนยัน → เตือนอัตโนมัติทุกเช้า 09:00 นับครั้งที่เตือน
- Power Automate เขียนเวลายืนยันกลับเข้าระบบ → เปลี่ยนสถานะเป็น Confirmed → ตัดสต็อกอุปกรณ์ต่อพ่วง

**Setup**
- Setup ต้องเสร็จก่อนวันเริ่มงานพนักงานอย่างน้อย 1 วัน
- การแก้ Checklist template มีผลกับงานที่สร้างใหม่เท่านั้น งานที่ทำค้างใช้ revision เดิม

## 6. การคืนอุปกรณ์เมื่อพนักงานลาออก (Offboarding)

Checklist 12 ข้อบังคับทำครบก่อนปิดเรื่อง:
```
1  สำรองข้อมูลผู้ใช้ขึ้น OneDrive / File Server
2  ให้ผู้ใช้ยืนยันว่าย้ายข้อมูลส่วนตัวออกแล้ว
3  ถอนสิทธิ์ Local Administrator
4  ปิดใช้งานบัญชี Active Directory
5  ยกเลิกสิทธิ์ Microsoft 365 และโอนกล่องจดหมายให้หัวหน้า
6  ถอนบัญชีออกจากระบบ VPN
7  ลบ User Code เครื่องพิมพ์
8  ถอดเครื่องออกจาก Domain และลบ Computer Object
9  ล้างข้อมูลในเครื่อง (Secure Wipe) และลง Windows ใหม่
10 ถอนไลเซนส์ซอฟต์แวร์ที่ผูกกับผู้ใช้
11 เปลี่ยนสถานะทรัพย์สินเป็น Available หรือ Retired
12 แจ้ง HR ว่าคืนอุปกรณ์ครบและปิดบัญชีเรียบร้อย
```
- อีเมลยืนยันคืนส่งได้เมื่อคืนครบทุกรายการเท่านั้น
- ค้างคืนเกินวันสุดท้ายของการทำงาน → แจ้ง HR หักจากเงินเดือนงวดสุดท้าย

## 8. ความปลอดภัย

**การเข้าสู่ระบบ**
- SSO ผ่าน Microsoft Entra ID เป็นวิธีหลัก
- ชื่อผู้ใช้ + รหัสผ่าน AD เป็นทางสำรองกรณี SSO ล่ม
- บัญชีนอก AD เฉพาะผู้ขาย/ผู้รับเหมา บังคับตั้งวันหมดอายุ
- MFA บังคับกับ SUPERADMIN และ IT_ADMIN
- จำกัดการเข้าจากนอกองค์กร ต้องผ่าน VPN

**นโยบายรหัสผ่าน (เฉพาะบัญชีนอก AD)**
```
ความยาวขั้นต่ำ 12 · ต้องมีตัวใหญ่ ตัวเล็ก ตัวเลข อักขระพิเศษ
เปลี่ยนทุก 90 วัน · ห้ามซ้ำ 5 ครั้งล่าสุด
ล็อกบัญชีเมื่อกรอกผิด 5 ครั้ง ล็อก 30 นาที
Session 30 นาทีเมื่อไม่มีการใช้งาน · บังคับออกทุก 12 ชั่วโมง
เก็บบันทึกการเข้าสู่ระบบ 365 วัน
```

## 11. ข้อจำกัดการลบข้อมูลหลัก

ลบไม่ได้เมื่อยังมีข้อมูลอ้างอิง — คืน HTTP 409 พร้อมจำนวนที่อ้างอิงอยู่ และ UI ต้องล็อกปุ่มลบพร้อม tooltip บอกเหตุผล

| ข้อมูลหลัก | ลบไม่ได้เมื่อ |
| --- | --- |
| หมวดทรัพย์สิน | มีทรัพย์สินผูกอยู่ |
| บริษัท | มีทรัพย์สินหรือผู้ใช้ผูกอยู่ |
| ที่ตั้ง / ยี่ห้อ / ผู้ขาย | มีทรัพย์สินอ้างอิง |
| หมวดใน Checklist | ยังมีหัวข้อในหมวด |
| ชุด Checklist | มีงานที่ใช้ชุดนี้อยู่ |
