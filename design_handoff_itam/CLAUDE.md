# CLAUDE.md — คำสั่งสำหรับ Claude Code

> วางไฟล์นี้ไว้ที่รากของโปรเจกต์ที่จะพัฒนา แล้วสั่ง Claude Code ทำงานทีละ Phase

## บริบท

กำลังสร้าง **ระบบบริหารทรัพย์สินไอที (ITAM)** สำหรับองค์กรหลายบริษัทในเครือ
ต้นแบบหน้าจอและสเปกครบอยู่ในโฟลเดอร์นี้ — อ่านตามลำดับ:

1. `README.md` — ภาพรวม สถาปัตยกรรม แผนการทำงาน 5 Phase
2. `BUSINESS-RULES.md` — **อ่านก่อนเขียนโค้ดใด ๆ** กฎ company scope และการอนุมัติเป็นหัวใจของระบบ
3. `DATA-MODEL.md` — entity, enum, API endpoint, background job
4. `SCREENS.md` — หน้าจอทั้งหมดและเนื้อหาแต่ละหน้า
5. `DESIGN-TOKENS.md` — สี ตัวอักษร ระยะห่าง component pattern
6. `INTEGRATIONS.md` — AD, Entra, GLPI, Power Automate, MS Forms, SMTP, ERP

ไฟล์ `.dc.html` เป็นต้นแบบ — เปิดในเบราว์เซอร์ดูได้ **แต่ห้ามคัดลอกโค้ดไปใช้ตรง ๆ** ให้สร้างขึ้นใหม่ด้วย React + TypeScript ตาม pattern ของโค้ดเบส

## กฎที่ห้ามละเมิด

1. **Company scope** — ทุก query กรองด้วย `companyId` ของผู้ใช้ที่ล็อกอิน บังคับที่ชั้น repository หรือ row-level security **ห้ามพึ่ง UI** ทรัพย์สินต่างบริษัทต้องคืน 404 ไม่ใช่ 403
2. **การอนุมัติยืม–คืนมีขั้นเดียว** — IT Admin ของบริษัทเจ้าของทรัพย์สิน ห้ามสร้าง approval chain ตามมูลค่าหรือสายบังคับบัญชา
3. **AD อ่านอย่างเดียว** — ห้ามเขียนข้อมูลผู้ใช้กลับไปที่ AD
4. **ค่าเสื่อมเป็น snapshot รายเดือน** — ห้ามคำนวณสดตอน query
5. **ค่าเงินใช้ decimal หรือ integer สตางค์** — ห้ามใช้ float
6. **ทุก entity มี audit trail** — บันทึกค่าเดิม/ค่าใหม่ ผู้ทำ และ source (UI/API/ADSync/Job)
7. **ข้อมูลหลักที่มีของอ้างอิงอยู่ลบไม่ได้** — คืน 409 พร้อมจำนวนที่อ้างอิง และ UI ล็อกปุ่มลบพร้อม tooltip

## วิธีทำงาน

- ทำทีละ Phase ตาม `README.md` อย่าข้าม
- แต่ละ Phase ให้เขียน migration + API + test ก่อน แล้วค่อยทำ UI
- ตัวเลขทุกตัวในต้นแบบเป็นข้อมูลตัวอย่าง — ต้องมาจาก API จริงเสมอ
- ทุกหน้าจอต้องรองรับสถานะครบตาม `ITAM States.dc.html`: กำลังโหลด (skeleton) · ยังไม่มีข้อมูล · ค้นหาไม่พบ · ผิดพลาด · ไม่มีสิทธิ์
- ข้อความ error ติดกับฟิลด์ ไม่ใช่ alert รวม
- Toast ตำแหน่งเดียวกันทุกหน้า หายเองใน 3 วินาที
- ภาษาไทยเป็นหลัก ใช้ปี พ.ศ. ตามค่าที่ตั้งไว้ในระบบ

## ข้อกำหนดที่มักถูกลืม

- หน้าจอมือถือต้องทำงานออฟไลน์ได้และซิงก์เมื่อมีสัญญาณ (PWA + IndexedDB) hit target ≥ 44px
- Checklist template เก็บเป็น revision — งานที่ทำค้างต้องใช้ revision เดิม
- เครื่องหมุนเวียนต้องมีบันทึกการล้างข้อมูลครบก่อนกดส่งมอบ
- อีเมลยืนยันคืนอุปกรณ์ส่งได้เมื่อคืนครบทุกรายการเท่านั้น
- มีสวิตช์ปิดอนิเมชันทั้งหมด และเคารพ `prefers-reduced-motion`
- เอกสารพิมพ์ต้องลง A4 หน้าเดียวพอดี

## สิ่งที่ควรถามก่อนตัดสินใจเอง

- โครงสร้างบริษัทในเครือจริง (ต้นแบบใช้ 4 บริษัทเป็นตัวอย่าง)
- รหัสกลุ่มใน AD ที่จะใช้ map บทบาทจริง
- ผังบัญชีและรูปแบบไฟล์ที่ฝ่ายบัญชีต้องการ
- SLA จริงของงานซ่อมแต่ละระดับความเร่งด่วน
